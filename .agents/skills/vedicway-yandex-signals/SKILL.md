# Yandex-сигналы VedicWay

Собирай только данные, которые меняют выбор темы или решение об обновлении статьи. Сырые ответы сохраняй через `$vedicway-seo-ledger` до интерпретации.

## Защита владельца данных

Для Webmaster и Metrika сначала прочитай `VEDICWAY_YANDEX_HOST_ID` и `VEDICWAY_METRIKA_COUNTER_ID`, затем вызови списки сайтов и счетчиков. Продолжай только при точном совпадении ID и публичного домена VedicWay. Не выбирай первый доступный объект. Несовпадение завершает только соответствующую ветку как `blocked`; данные чужого проекта не сохраняй даже временно. Wordstat и Yandex Search при этом остаются доступными источниками спроса.

## Сбор

Для новой темы всегда возьми Wordstat top requests по узкому seed и нужному региону, затем проверь интент выдачей Yandex Search. Если за последние 28 полных дней Metrika накопила меньше 100 органических визитов или Webmaster вернул меньше 30 показов по поисковым запросам, считай поведенческие данные недостаточными и ранжируй темы по Wordstat, SERP-интенту и риску каннибализации. Отсутствие host ID, counter ID либо прав к этим двум продуктам не блокирует исследование спроса. После raw response запиши query, затем отдельный `serp-snapshot` с тем же region ID. Поле `checksum` не передавай: реестр сам канонизирует массив результатов, вычисляет SHA-256 и возвращает его. Сохрани частотность вместе с датой, регионом и формой запроса. Не смешивай абсолютную частотность, динамику и данные Webmaster в одно число.

До серии запросов проверь Wordstat одним канареечным seed, затем проверь Yandex Search одним канареечным запросом. Каждый из них считается единственным подтверждающим вызовом своего источника. При первой ошибке доступа, квоты либо `Permission denied` не повторяй вызов этого источника. Сохрани raw response обоих канареечных вызовов; если хотя бы один источник недоступен, прекрати внешние попытки, не создавай `query`, `serp-snapshot` или `cluster` без реальных частотностей и результатов выдачи, затем заверши run как `blocked` с точными названиями недоступных источников. Полную серию начинай только после двух успешных канареечных ответов. Пустой или ошибочный ответ нельзя превращать в seed-query, предварительный SERP либо ready-кластер.

Для опубликованных страниц бери Webmaster queries и indexing status, затем Metrika organic landing report. Один снимок всегда содержит одинаковое окно дат и точный URL статьи. Запрос на переобход выполняй только через отдельное одобренное optimization_action.

## Доказательства

В `request_hash` включай имя инструмента, параметры, host_id или counter_id и окно дат. В `response` сохраняй исходный JSON без токенов. В выводе указывай, какие гипотезы подтвердились и какие данные их опровергли.

Прочитай [правила идентичности и свежести](references/identity-guard.md) до первого MCP-вызова.
