# Yandex-сигналы VedicWay

Собирай только данные, которые меняют выбор темы или решение об обновлении статьи. Сырые ответы сохраняй через `$vedicway-seo-ledger` до интерпретации.

## Защита владельца данных

Сначала прочитай `VEDICWAY_YANDEX_HOST_ID` и `VEDICWAY_METRIKA_COUNTER_ID`. В Webmaster вызови список сайтов, в Metrika список счетчиков. Продолжай только при точном совпадении ID и публичного домена VedicWay. Не выбирай первый доступный сайт или счетчик. Несовпадение завершает run как `blocked`; данные Ивана не сохраняй даже временно.

## Сбор

Для новой темы возьми Wordstat top requests по узкому seed и нужному региону, затем проверь интент выдачей Yandex Search. После raw response запиши query, затем отдельный `serp-snapshot` с тем же region ID и checksum канонического массива результатов. Сохрани частотность вместе с датой, регионом и формой запроса. Не смешивай абсолютную частотность, динамику и данные Webmaster в одно число.

Для опубликованных страниц бери Webmaster queries и indexing status, затем Metrika organic landing report. Один снимок всегда содержит одинаковое окно дат и точный URL статьи. Запрос на переобход выполняй только через отдельное одобренное optimization_action.

## Доказательства

В `request_hash` включай имя инструмента, параметры, host_id или counter_id и окно дат. В `response` сохраняй исходный JSON без токенов. В выводе указывай, какие гипотезы подтвердились и какие данные их опровергли.

Прочитай [правила идентичности и свежести](references/identity-guard.md) до первого MCP-вызова.
