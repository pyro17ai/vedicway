# Планировщик тем VedicWay

Одна тема должна отвечать на один поисковый интент и вести к осмысленному следующему действию на VedicWay. Не создавай механические серии по всем знакам, домам и планетам без отдельного спроса и уникальной практической ценности.

## Кластеризация

Сначала раздели информационные запросы, запросы о расчете карты и навигационные формулировки. Объединяй запросы только когда выдача пересекается по смыслу и одна статья может полностью закрыть вопрос. Разделяй темы, если пользователю нужны разные ответы, даже при похожих словах.

Сверь кандидат с уже опубликованными URL и существующими кластерами. При каннибализации расширь старую статью или отклони новый кластер. Новый slug использует латиницу, остается читаемым и не меняется после публикации.

## Приоритет

Оцени тему по формуле `0.35 * demand + 0.25 * business_fit + 0.20 * evidence_gap + 0.20 * authority_fit`, нормируя каждую часть от 0 до 100. `business_fit` выше у тем, где расчет натальной карты естественно продолжает материал. `authority_fit` падает до нуля, если для ответа нужны медицинские, юридические или гарантированные предсказания.

Запиши query records, затем cluster со статусом `ready`, rationale и связанными query_ids через `$vedicway-seo-ledger`. Не готовь бриф в этом Skill.
