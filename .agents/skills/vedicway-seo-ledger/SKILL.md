# SEO-реестр VedicWay

Этот Skill задает единственную границу записи служебного состояния. Работай только через `vedicway-control` MCP и не запускай shell, Python CLI или произвольный SQL.

## Обязательный порядок

1. В начале вызови `vedicway_ledger_health`. Инструмент применит только штатные миграции схемы и вернет состояние реестра.
2. Scheduler уже создал `cron_run` и передал его служебному MCP. Для эксклюзивной работы вызови `vedicway_ledger_claim` с нужной сущностью. Сохрани `claim_token`; без него нельзя менять захваченный объект.
3. Каждый ответ внешнего MCP сначала запиши через `vedicway_ledger_write` с `record_type=tool-response`, затем извлекай запросы или метрики. Ответы самого `vedicway-control` уже находятся внутри границы реестра: health, claim, чтение очереди и результаты записи повторно как tool-response не сохраняй. Остальные сущности записывай тем же инструментом с типом из контракта и объектом `payload`; промежуточные JSON-файлы не создавай.
4. После выполнения работы вызови `vedicway_record_run_log` ровно один раз. Передай только короткий `log_text` с ходом работы и возникшими ошибками; не включай токены, cookie и персональные данные.
5. Заверши run ровно одним вызовом `vedicway_record_result`. Для `completed` передай `artifact` с идентификаторами созданных записей или подтвержденной публикацией; пустой объект отклоняется. `skipped` допустим только при доказанном отсутствии готовых сущностей. Недостающие доступы дают `blocked` с именами секретов без их значений.

## Запреты

Не запускай shell, Python REPL, `psql` или GUI. Не меняй terminal-состояние публикации задним числом. Не переиспользуй `attempt_token`, `idempotency_key` или просроченный `claim_token`. Не записывай токены, cookie, персональные данные и полные HTTP-заголовки.

Перед записью сущностей прочитай [контракт записей](references/record-contracts.md).
