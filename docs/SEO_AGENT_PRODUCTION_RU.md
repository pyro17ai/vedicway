# SEO-агент VedicWay в production

## Состав контура

Агент ежедневно исследует спрос, готовит и публикует одну одобренную статью в `/blog`, затем создает отдельную статью в редакторе Дзена через Playwright. Для Pinterest он готовит десять разных вертикальных карточек 1000x1500 и загружает их одним пакетом через Business CSV UI, а VK получает короткий пост с проверенной ссылкой на VedicWay. Браузерные профили VedicWay создаются пустыми и не содержат сессий другого проекта.

Служебная память хранится в отдельной схеме PostgreSQL `seo_agent`. Типизированный ledger связывает исходный бриф, draft, медиа, HTTP-попытку и внешний ID публикации. Повторный запуск использует тот же idempotency key, а terminal-записи нельзя переписать задним числом. Публикация на сайте проходит через закрытый FastAPI с отдельным bearer-токеном; административные cookie агент не получает.

В образ входят восемь изолированных MCP: четыре источника Yandex, VK, два Playwright-публикатора и служебный `vedicway-control`. Control хранит реестр, публикует сайт и импортирует уже созданные изображения из `CODEX_HOME/generated_images`; генерацией он не занимается. Обложки и Pinterest-карточки создаёт системный `$imagegen` через встроенный `image_gen` tool в авторизованном Codex CLI. SEO-контур не монтирует и не читает `OPENAI_API_KEY`.

## Расписание и первый запуск

`article_intelligence_refresh`, `article_content_production`, `article_site_publish`, `dzen_daily_publish`, `vk_daily_publish` и `article_optimization` запускаются раз в 1440 минут. Pinterest-задание стартует один раз в сутки в 12:00 по Москве, формирует десятистрочный CSV и назначает пины на 13:00-22:00 с часовым шагом. `article_lifecycle_review` работает раз в неделю. Каждое задание использует leases ledger; сбой оставляет доказательство попытки и освобождает незавершенные claims.

Новая установка создает пустую схему. Старый bootstrap с CSV отключен по умолчанию и включается только через `VEDICWAY_SEO_BOOTSTRAP_SEEDS=1`, поэтому production не наследует тестовые темы, публикации и результаты донора. Первый intelligence-run начинает с Wordstat и Yandex Search.

Wordstat остается рабочей веткой при молодом сайте. Порог достаточности задан явно: минимум 100 органических визитов Metrika и 30 показов Webmaster за 28 полных дней. Пока любой порог не достигнут, planner использует частотность Wordstat, SERP-интент и проверку каннибализации. Несовпадающий host ID либо counter ID блокирует только чужой источник данных; агент не выбирает первый доступный ресурс аккаунта.

## Доставка по площадкам

Сайт принимает HTML и медиа после короткой редакционной проверки, отвечает публичным URL и подтверждает canonical, JSON-LD и sitemap. Обложка и десять Pinterest-карточек создаются отдельными навыками VedicWay, которые вызывают системный `$imagegen` по одному разу на каждый финальный файл. Дзен-публикатор открывает Студию, заполняет реальный редактор, перечитывает автосохраненный черновик и только затем нажимает публикацию. RSS сайта сохраняется как отдельная техническая лента и не участвует в production-публикации Дзена.

VK Skill сам вызывает VK MCP, затем проверяет точный `post_id` через `wall.get`; control в этом пути не участвует. Pinterest-публикатор через Playwright собирает CSV из десяти строк прямо в странице, передает его в `#csv-input` и принимает результат только по точной фразе интерфейса о начале обработки файла.

## Активация

До активации `VEDICWAY_SEO_AGENT_ENABLED` остается равным `0`, а Compose-профиль `seo` не запускается. Список недостающих реквизитов хранится в [OPEN_GATES_RU.md](../seo_agent/OPEN_GATES_RU.md). После заполнения секретов release-check проверяет девять MCP, 18 Skills, восемь заданий, точные Yandex ID и наличие реквизитов VK/Pinterest. Запуск выполняется отдельной командой `docker compose --profile seo up -d seo-agent`; обычный `docker compose up` агент не включает.
