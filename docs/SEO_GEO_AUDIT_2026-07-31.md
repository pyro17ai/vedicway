# Полный SEO- и GEO-аудит VedicWay

Дата контрольного среза: 31 июля 2026 года. Продакшен: https://vedicway.ru. Активный релиз на VPS: `/opt/vedicway/releases/0a4244764938d57f4a6f6454d592de4f1c2e0385-r4`.

## Итоговая оценка

Внутренний комплексный SEO score вырос с **58/100 до 87/100**. Это расчёт аудита VedicWay, а не показатель Яндекса, Google или Lighthouse. Одна и та же формула применена к исходному и итоговому состоянию:

`SEO score = On-page × 55% + архитектура × 20% + производительность × 10% + GEO/entity × 10% + внешние сигналы × 5%`.

## Охват и метод

Аудит объединил все 17 SEO- и GEO-навыков из подключённых плагинов. Из Marketing Skills применены SEO audit, site architecture, programmatic SEO, schema и AI SEO. Из SEO Optimization применены competitor analysis, content gap analysis, content quality auditor, content writer, domain authority auditor, GEO content optimizer, keyword research, offsite signal analyzer, on-page SEO checker, page play builder, performance monitor и rank tracker.

Проверка охватила исходный HTML, DOM после JavaScript, HTTP-заголовки, `robots.txt`, sitemap, RSS для Дзена, `llms.txt`, JSON-LD, внутренний граф, изображения, весь корпус из 202 подготовленных материалов и каждую из 29 опубликованных статей. Семантика собрана через Яндекс Поиск и Wordstat. Продакшен дополнительно проверен обычным Chrome после выкладки r4.

## Исходное состояние

До правок sitemap содержал шесть адресов, при этом guide и blog были пустыми. В фактическом обходе находилось десять индексируемых страниц, но семь из них отдавали в исходном HTML тело главной. Сборка дважды запускала SEO-пререндер, поэтому на главной дублировались JSON-LD, preload и код Метрики. Пустые хабы оставались индексируемыми; приватные `/chart/:id` и `/rectification/:id` наследовали метаданные главной; RSS и динамические страницы отвечали 405 на HEAD. На служебных URL с query string пропадал `X-Robots-Tag`, а код подтверждения мог попадать в Referer.

On-page слой страдал от отсутствия опубликованного тематического кластера. Внутренний корпус уже содержал 202 подготовленные статьи, но API guide и blog возвращали ноль. Встречались длинные title, повторяющиеся редакционные формулы, три битые внутренние ссылки и ссылки на первоисточник по незашифрованному HTTP. У сервиса не было устойчивой поисковой сущности: `site:vedicway.ru` не давал результатов, точных внешних упоминаний бренда не найдено, а название VedicWay пересекается с чужими проектами.

Начальный мобильный Lighthouse: Performance 71, SEO 100, Accessibility 83, Best Practices 100. FCP составлял 2,2 с, LCP 4,0 с, TBT 350 мс, CLS 0, Speed Index 6,2 с. Передавалось около 1,07 МБ; главный JavaScript содержал 71 КБ неиспользуемого кода, CSS — 27 КБ.

## Архитектура после правок

Карта сайта содержит 34 индексируемых URL: главную, `/guide`, три страницы доверия и 29 статей. Финальный обход дополнительно проверил `/blog` и четыре юридические страницы. Эти пять страниц имеют согласованный `noindex, follow`; число индексируемых URL поэтому равно числу URL в sitemap: 34 из 34.

| Объект | Итог |
|---|---:|
| URL в sitemap | 34 |
| Индексируемые URL | 34 |
| Опубликованные статьи | 29 |
| Страницы полного контрольного crawl | 39 |
| Уникальные внутренние цели | 35 |
| Битые внутренние ссылки | 0 |
| Дубли title, description или canonical | 0 |
| Невалидные JSON-LD | 0 |
| Страницы с числом H1, отличным от одного | 0 |
| Ошибки HTTP среди проверяемых страниц | 0 |

Неизвестная статья возвращает настоящий 404 с `noindex`. HTTP и `www` перенаправляются на основной HTTPS-домен. Приватные карты и ректификация теперь получают отдельный исходный HTML с собственным H1, `noindex, nofollow, noarchive` и без публичного canonical. Аналогичный заголовок действует при наличии query string. `/access/confirm` отдаёт `Referrer-Policy: no-referrer`; recovery и privacy request также защищены от индексации.

Динамические страницы guide, статьи, sitemap и `/feed/dzen.xml` отвечают 200 на GET и HEAD. RSS содержит 29 уникальных материалов и ведёт канал на `/guide`, а не на пустой `/blog`. `robots.txt` закрывает API и приватные пространства, сохраняя доступ робота к noindex-страницам. `llms.txt` содержит девять публичных ссылок, включая три опорных материала. Manifest отдаётся с `application/manifest+json`.

## On-page и контент

Все 29 статей возвращают полный материал в исходном HTML. Объём составляет 1001–1835 слов, медиана — 1403. Title укладываются в 50–60 знаков, descriptions после финальной правки — в 118–148. У каждой страницы один H1, self-canonical, `index, follow`, дата публикации и изменения, Article вместе с BreadcrumbList. Уникальность title, description, focus keyphrase и canonical подтверждена для всей когорты.

В статьях есть 60 видимых ссылок на источники, по одной–четыре на материал. Каждая citation из JSON-LD продублирована в видимом блоке. После правок у 29 из 29 материалов есть внешний источник; ссылки Gretil переведены на HTTPS, а материал о системах домов получил первичную техническую документацию Swiss Ephemeris вместо единственной внутренней ссылки. Проверено 115 уникальных изображений и вариантов `srcset`: все отвечают 200. У 145 элементов `img` задан `alt`; пустые значения оставлены только у декоративных изображений.

Весь подготовленный корпус содержит 202 статьи: 41 по основам, 55 о планетах и домах, 44 о времени и циклах, 62 по практике чтения. Медиана — 1258 слов; 171 материал длиннее 800 слов, остальные длиннее 596. Во всём корпусе нет битых внутренних ссылок и повторяющихся title, description, focus keyphrase или canonical. Первая индексируемая когорта ограничена 29 взаимосвязанными материалами: 22 уровня «Новичок» и семь уровня «Эксперт». Остальные 173 материала не публиковались массово, чтобы новый домен не получил сотни страниц до первой индексации и накопления поведенческих данных.

Главный H1 после JavaScript читается как «ВЕДИЧЕСКАЯ НАТАЛЬНАЯ КАРТА ОНЛАЙН» с корректным пробелом. Юридические документы остаются полностью доступными человеку после загрузки приложения, но исключены из поискового индекса, поскольку основной текст зависит от JavaScript. Страницы `/about`, `/methodology` и `/editorial-policy` уже в первом HTML получают собственные title, description, canonical, H1 и содержательный вводный текст.

## Schema.org и сущность

Главная публикует Organization, WebSite, WebApplication и FAQPage. Организация связана с сайтом через устойчивый `@id`, содержит юридическое имя оператора, ИНН, ОГРНИП, email и логотип. Статьи используют Article с publisher, author, headline, image, датами, articleSection, educationalLevel, about и citation. Хабы используют CollectionPage и BreadcrumbList, страницы доверия — AboutPage или WebPage.

Сущность VedicWay теперь подкреплена страницами об операторе, методологии и редакционной политике. В Chrome на `/about` видны ИП Корольский Вадимир Васильевич, ИНН 722407070173, ОГРНИП 311723232700200 и адрес для обращений. Доказательная база статей стала пригодной для цитирования поисковыми и генеративными системами: определения даны до длинного контекста, ограничения метода вынесены в текст, источники доступны человеку и машине.

Слабое место GEO сохраняется в авторстве. Все 29 материалов подписаны коллективным автором «Редакция VedicWay»; именованного редактора с биографией и квалификацией нет. Это ослабляет E-E-A-T и вероятность прямой атрибуции ответа. Добавлять вымышленного специалиста запрещено: нужен реальный человек, его компетенции и публичная страница автора.

## GEO, авторитет домена и внешние сигналы

На момент аудита Яндекс не показывает страницы по оператору `site:vedicway.ru`, а точных внешних упоминаний домена и бренда нет. Ссылочный профиль равен нулю. Название пересекается с другим проектом VedicWay, связанным с Marianna Polonsky, поэтому каждой внешней публикации нужно использовать полную связку «VedicWay.ru — ведическая натальная карта» и адрес `https://vedicway.ru`.

Техническая готовность к GEO высокая: сущность связана через schema, источники видимы, определения кратки, ограничения присутствуют, `llms.txt` опубликован. Фактический авторитет возникнет после индексации, цитат и упоминаний с независимых площадок. Покупка массовых ссылок или имитация авторских профилей ухудшит доверие и в score не засчитывается.

## Производительность и доступность

После оптимизации логотип в шапке и подвале уменьшен со 124 КБ до 8 КБ, повторная SEO-вставка удалена, а главный JavaScript собирается без лишнего второго пререндера. Финальный мобильный Lighthouse: Performance 75, SEO 100, Accessibility 83, Best Practices 100. FCP — 2,1 с, LCP — 3,9 с, TBT — 230 мс, CLS — 0, Speed Index — 6,6 с, TTI — 3,9 с. Передаётся около 1,08 МБ.

VPS не ограничивает текущую производительность: load average во время диагностики составлял 0,18/0,24/0,26, свободно 4,9 ГБ RAM, диск занят на 20%, рестартов и OOM нет. Локальный Nginx отвечает за 76–83 мс, прямой origin показывает TTFB 1,03–1,41 с, а публичный Timeweb edge — 2,48–2,77 с. Редкие 503 при четырёх параллельных Chromium-запросах возникают на внешнем PHP-шлюзе Timeweb; последовательный crawl проходит без ошибок. Следующий прирост LCP требует убрать этот шлюз или увеличить его пул соединений, затем разделить главный JavaScript и сократить CSS.

На странице присутствует идентификатор Метрики `111176610`; скрипт загружается только после согласия на аналитические cookies. Файл подтверждения Яндекс Вебмастера опубликован. Служебное MCP-подключение в текущей среде авторизовано в другом аккаунте Яндекса и не видит vedicway.ru, поэтому реальные данные обхода, индекса и визитов из интерфейсов Яндекса в оценку не подмешивались.

## Внесённые изменения

Исправлены пререндер и метаданные главной, хабов, страниц доверия, юридических и приватных маршрутов. Удалены повторные JSON-LD, preload и код Метрики; выровнены canonical, robots, Open Graph, alt и schema. Добавлены корректные заголовки для служебных URL с query string, отдельный `no-referrer` для подтверждения доступа, настоящий 404 и MIME manifest. Sitemap, RSS, `robots.txt`, `llms.txt` и Nginx приведены к одной политике индексации.

Опубликована замкнутая когорта из 29 статей. Исправлены длинные title и description, повторяющиеся формулы, три битые внутренние ссылки, HTTP-источники и слабая citation одной статьи. Публикатор теперь блокирует ссылку на материал за пределами выбранной когорты и проверяет citation внутри schema. Последняя публикация завершилась со статусом `verified`: 29 Article-схем, 29 responsive-обложек, 29 блоков рекомендаций и по два CTA.

## Оставшиеся ограничения

Индекс, позиции, ссылки и упоминания нельзя создать техническим деплоем. Сейчас они равны нулю и удерживают score ниже 90. Второе ограничение — коллективный автор без реального экспертного профиля. Третье — внешний Timeweb edge, который замедляет TTFB и может вернуть 503 при коротком параллельном всплеске. Полевого CrUX и накопленной статистики Метрики ещё нет; повторную оценку нужно делать после 28 дней данных.

Зарезервированная калибровка CORE/CITE не подменялась внутренним score, поскольку для неё нет полевых и внешних данных:
