# VedicWay: контракт изображений для статей

## Граница ответственности

Редактор не записывает бинарные файлы и `data:` URL в статью или `localStorage`. В production он отправляет файл в медиасервис, а статья хранит только `id`, неизменяемый `storageKey`, публичные URL производных файлов и редакционные метаданные. Локальный режим без backend явно использует IndexedDB с провайдером `dev-indexeddb`; такой материал нельзя считать production-публикацией.

## Загрузка

`POST /api/v1/admin/media`, `multipart/form-data`, только для администратора с действующей same-site сессией и CSRF-защитой. Поля:

- `file`: JPEG, PNG, WebP или AVIF, до 12 МБ. SVG и любые исполняемые форматы запрещены;
- `purpose`: `cover` или `body`;
- `alt`: обязательное текстовое описание, `title` и `caption`: необязательные строки.

Сервис декодирует файл библиотекой обработки изображений, игнорирует исходное расширение, удаляет EXIF/GPS, проверяет реальную сигнатуру и размеры. Для публикации он создаёт варианты шириной 640, 960, 1280 и 1600 px без увеличения маленького оригинала, сохраняет WebP или AVIF и исходный безопасно перекодированный fallback. Object storage закрыт для записи снаружи; публичный CDN выдаёт только производные файлы. `storageKey` никогда не строится из имени загруженного файла.

Успешный ответ `201`:

```json
{
  "asset": {
    "id": "uuid",
    "storageKey": "articles/uuid/original.webp",
    "url": "/media/articles/uuid/1600.webp",
    "sources": [
      { "url": "/media/articles/uuid/640.webp", "width": 640, "mimeType": "image/webp" },
      { "url": "/media/articles/uuid/1280.webp", "width": 1280, "mimeType": "image/webp" }
    ],
    "width": 1600,
    "height": 900,
    "mimeType": "image/webp",
    "sizeBytes": 184321,
    "alt": "Круг натальной карты на тёмном фоне",
    "title": "Натальная карта",
    "caption": "Пример расположения домов",
    "createdAt": "2026-07-19T00:00:00Z"
  }
}
```

## Использование и удаление

Обложка хранится в `article.coverImage`, изображения текста — в `article.bodyMedia`. Положение внутри статьи задаёт отдельный безопасный маркер `{{media:<id>}}`; редактор не принимает произвольный HTML. Публичный рендер сопоставляет маркер только с медиа текущей статьи и создаёт `<figure>`, `<img>` и `<figcaption>` через React.

Удаление статьи сначала снимает ссылки на assets. Физический объект удаляет фоновая сборка мусора после периода восстановления, когда ни одна версия статьи его больше не использует. API удаления: `DELETE /api/v1/admin/media/{id}` с проверкой администратора и CSRF; занятый asset возвращает `409 MEDIA_IN_USE`.

## Раскладка

Обложки карточек и верх статьи используют `aspect-ratio: 16 / 9`, `object-fit: cover` и центрированную точку кадрирования. Внутреннее изображение занимает ширину текстовой колонки, сохраняет тот же 16:9 контейнер и получает `srcset`/`sizes`. Размеры исходника заданы атрибутами `width` и `height`, поэтому загрузка не двигает страницу. Обязательный `alt` проверяется перед публикацией; декоративная картинка получает пустой `alt` только по явному признаку.
