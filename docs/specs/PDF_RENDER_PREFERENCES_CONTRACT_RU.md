# VedicWay: снимок настроек PDF

При каждом нажатии «Скачать PDF» frontend считывает текущие значения интерфейса и отправляет новый запрос. Готовый файл, созданный раньше с другими настройками, не скачивается напрямую.

`POST /api/v1/charts/{chart_id}/reports/pdf`:

```json
{
  "preferences": {
    "schema_version": "pdf-render-preferences.v1",
    "varga": "D24",
    "mode": "expert",
    "chart_style": "south_indian"
  }
}
```

`varga` проходит серверную проверку по разрешённому списку дробных карт. `mode` принимает `plain` или `expert`. Backend создаёт строку `pdf_render_requests` и вычисляет SHA-256 канонического JSON. Поле `preferences` после вставки не обновляется. Задача очереди получает `render_request_id`, а путь, checksum и размер готового файла записываются в ту же строку запроса. Токен скачивания подписывает пару `chart_id + render_request_id`, поэтому более поздний рендер не может подменить выбранный PDF. На диске хранятся только три последних готовых файла одной карты.

Frontend ждёт `GET /api/v1/charts/{chart_id}/reports/pdf/requests/{render_request_id}`. Статус общей карточки не используется для завершения скачивания: два параллельных запроса отслеживаются независимо.

PDF выбирает клетки указанной варги из уже рассчитанного `ChartSnapshot`; расчёт положений не повторяется и не меняется. В понятном режиме карта печатает короткие обозначения. Профессиональный режим печатает полные названия, градусы и ретроградность. Над картой всегда указаны выбранная варга, режим и южноиндийский стиль. Frontend скачивает файл только после того, как `render_request_id` готового report совпал с идентификатором нажатия, поэтому параллельный старый рендер не подменит результат.
